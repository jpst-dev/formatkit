# WPF UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A WPF app, `FormatKit.exe`, that runs a profile through an elevated worker, shows the preparation checklist, the read-only queries and catalogs, and (last phase) builds installation media, without changing the CLI's behavior.

**Architecture:** A new `FormatKit.Hosting` library takes the composition root and the shared flows out of `FormatKit.Cli`; the CLI and the new `FormatKit.App` both sit on it. The app runs unelevated and starts itself with `--worker` (through `runas` when needed) to run the engine; the two talk over a named pipe with one JSON message per line.

**Tech Stack:** .NET 10 (`net10.0-windows`), WPF with `ThemeMode="System"`, CommunityToolkit.Mvvm, System.Text.Json source generation, xunit.v3, Serilog.

**Spec:** `docs/superpowers/specs/2026-10-29-wpf-ui-design.md`

## Global Constraints

- `Directory.Build.props` sets `TreatWarningsAsErrors`; the only suppressed diagnostic is `WPF0001` in `FormatKit.App` (spec 4.2).
- All system access goes through `SystemAccess` interfaces; ViewModels never touch WPF types (they use `IDialogService`).
- User-facing text: `Resources/Strings.resx` plus `Strings.pt-BR.resx` in the project that shows it, both in sync. Code, comments, docs and commits in English.
- `FormatKit.App` publish settings match the CLI: `win-x64`, `PublishSingleFile`, self-contained on publish, `SatelliteResourceLanguages` `en;pt-BR`, `DebugType` `embedded`, `AssemblyName` `FormatKit`, `OutputType` `WinExe`.
- Pipe name `FormatKit-<guid>`; pipe ACL current user only; one connection; worker exits if no client within 30 seconds.
- Mutex name `Local\FormatKit.App`; the worker does not take it.
- Resume task arguments: CLI `run --resume --wait-on-exit` (unchanged), UI `--resume`.
- Last profile stored in `%LOCALAPPDATA%\FormatKit\app.json`, nothing else.
- Never put a password, passphrase, product key or remote URL in a pipe message or log.
- Commits: conventional style, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Unit tests before every commit: `dotnet test -- --filter-not-trait "Category=Integration"`. Never run system-changing commands on the host.
- Phase 7 (media) starts only after PR jpst-dev/formatkit#1 is merged into `main` and this branch is brought up to date; until then stop after Task 18.

## Review Focus

1. A profile path with spaces or non-ASCII characters must reach the worker intact through `runas` (arguments go through `ProcessStartInfo.ArgumentList`) — test in Task 13.
2. The profile file deleted or made invalid between review and Run must give a `failed` message with the profile errors, not a crash — test in Task 12.
3. A window that dies before connecting must not leave a worker running: the worker exits after 30 seconds without a client — test in Task 13.
4. A garbage, partial or unknown-type line on the pipe must be skipped and logged, never crash the reader — test in Task 11.
5. A second start (the user double-clicks while the resume window is open) must bring the first window forward and not start a second run — test in Task 6.
