# Cleanup (Sub-project 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the `cleanup` module: a JSON catalog of app-removal, privacy and performance tweaks in levels, applied through the run engine with an undo journal, plus `cleanup list`, `cleanup check` (read-only diagnosis) and `cleanup undo` commands.

**Architecture:** New system abstractions (registry, services, power schemes, AppX, optional features, user session) live in `FormatKit.Core.SystemAccess` and join `ServiceSet`. A new `FormatKit.Cleanup` project holds the embedded catalogs, typed action handlers (check / capture / apply / undo), the journal store, item selection, one engine step per category, the undo service and the diagnosis. The CLI registers the module and adds a `cleanup` command group.

**Tech Stack:** C# / .NET 10 (`net10.0-windows`), System.Text.Json (polymorphic records), Microsoft.Win32.Registry (in-box), System.Management (already referenced), System.CommandLine 2.0.14, xunit.v3, Serilog.

**Spec:** `docs/superpowers/specs/2026-10-27-cleanup-design.md`

## Global Constraints

- Target `net10.0-windows`, nullable on, `TreatWarningsAsErrors` (from `Directory.Build.props`). No new NuGet packages.
- Code, identifiers, comments, logs and repository docs in English. Every user-facing string in both `Resources/Strings.resx` (en) and `Resources/Strings.pt-BR.resx`, read through the project's `Localization/Strings` class.
- `FormatKit.Cleanup` references only `FormatKit.Core`. It never references `FormatKit.Drivers`.
- Never parse localized tool text. Parse only GUIDs, exit codes, numbers, or text the plan's own PowerShell snippet prints.
- Anything passed into a PowerShell command line (package names, feature names) must match `^[A-Za-z0-9._-]+$`; adapters throw `ArgumentException` otherwise.
- Registry paths in data and APIs use `HKLM\...` or `HKCU\...`, opened in the 64-bit view.
- Tests use fakes for every system abstraction. Tests that touch the real machine carry `[Trait("Category", "Integration")]` and may only write under `HKCU\Software\FormatKitTests`.
- Exit codes come from `FormatKit.Cli.ExitCodes`; no new codes.
- Commit after each task; messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Run the unit suite with `dotnet test -- --filter-not-trait "Category=Integration"`.

## Review Focus

1. **DWORD values above `int.MaxValue`** (`NetworkThrottlingIndex = 0xFFFFFFFF`) must round-trip through catalog, registry, journal and undo unchanged. Pinned in Task 1 and Task 7.
2. **String-typed values that look numeric** (`HKCU\Control Panel\Mouse\MouseSpeed` is `REG_SZ "1"`) must be restored with their original kind, not as DWORD. Pinned in Task 7.
3. **A crash between "journal written" and "change applied"** leaves an entry whose previous state equals the current state; undo must succeed and change nothing. Pinned in Task 9.
4. **Elevation with a different administrator account**: HKCU items are skipped with a reason, machine items still apply. Pinned in Task 8.
5. **pt-BR systems**: `powercfg` and `sc.exe` print localized text; adapters must work from GUIDs and exit codes only. Pinned in Task 2 with pt-BR sample output.
