# FormatKit Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public pt-BR/English static site for FormatKit in `site/`, generated from the repository's JSON catalogs and the GitHub Releases API, deployed to GitHub Pages from `release.yml`.

**Architecture:** Astro + Starlight. Pure TypeScript loader functions (`src/loaders/*`) parse and validate each data source and report warnings; `src/content.config.ts` wraps them as data collections. Components render entries for one locale; MDX pages in both locales embed them; catalog items are one custom route. Post-build checks guard locale parity, third-party hosts and command spelling.

**Tech Stack:** Node 24 LTS, Astro 7.4, @astrojs/starlight 0.42, zod (via `astro/zod`), vitest, Astro Container API for component tests, micromark, starlight-links-validator, GitHub Actions (`actions/upload-pages-artifact`, `actions/deploy-pages`).

**Spec:** `docs/superpowers/specs/2026-10-29-website-design.md` (decisions D1-D16; sections cited as §N).

## Global Constraints

- `site: 'https://jpst-dev.github.io'`, `base: '/formatkit'`; root locale pt-BR (`lang: 'pt-BR'`, label "Português"), `en` locale (label "English") at `/formatkit/en/` (D2).
- Same English slugs in both locales (D3); every docs page exists in both locales (D4).
- Only hard catalog errors: missing or duplicate `id`, missing `title`/`what`/`breaks` in `en` or `pt-BR` (D5). Everything else unknown is a warning.
- No external script, style, font, image or frame host in the build output; search is Pagefind (D16).
- Release notes are rendered with `micromark` with raw HTML off (D12).
- Env vars: `GITHUB_TOKEN` (optional), `FK_REQUIRE_RELEASE=1` (fail without a readable latest release), `FK_RELEASES_FILE=<path>` (read a saved API response) (§7).
- The page never says "faster", "FPS" or a percentage gain of its own on the Measurements page (§8).
- Repo text is English; site copy exists in pt-BR and English. Commands keep the README spelling.
- Never run FormatKit's system-changing commands on the host; screenshots are taken in the test VM.
- Commits: conventional style, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push or merge without the user's OK.

## Review Focus

- Catalog text containing `<`, `&` or backslashes (registry paths such as `HKLM:\SOFTWARE\...`) must render literally, never as HTML — pinned in Task 11.
- Two item ids that differ only by case would collide on case-insensitive file systems (Windows checkouts) and confuse URLs — Task 10 makes it a hard error.
- An unauthenticated local build hitting the GitHub rate limit (HTTP 403) must take the "no release" path, not crash — pinned in Task 3.
- A release with an empty or null body must show "no notes" in the changelog, not "null" — pinned in Task 4.
- Internal links written without the `/formatkit` base (`/download/`) work in dev and break on Pages — Task 7's dist check rejects root-relative hrefs that do not start with `/formatkit/`.

### Task 3: Releases loader

**Files:**
- Create: `site/src/loaders/releases.ts`, `site/tests/fixtures/releases/{with-digests,no-digests,only-prereleases,empty}.json`, `site/tests/fixtures/releases/SHA256SUMS.txt`

- Test: `site/tests/releases.test.ts`

**Interfaces:**
- Produces:
  - `type ReleaseAsset = { name: string; url: string; size: number; sha256: string | null }`
  - `type Release = { id: string /* tag */; tag: string; name: string; date: string; url: string; prerelease: boolean; body: string; assets: ReleaseAsset[] }`
  - `type ReleasesResult = { releases: Release[]; latest: Release | null }`
  - `loadReleases(opts: { fetch: typeof fetch; env: Record<string, string | undefined> }): Promise<ReleasesResult>`
  - Collection `releases`: one entry per release, plus `latest` exposed by `getLatestRelease(): Promise<Release | null>` in the same file (reads the collection).

Rules (§7): drafts dropped; newest first by `published_at`; `latest` = newest non-prerelease; assets kept: `FormatKitUI.exe`, `formatkit.exe`, `SHA256SUMS.txt`; `sha256` from `digest` (`sha256:` prefix stripped, lower case), else from `SHA256SUMS.txt` lines `<hash>  <name>`; `body` null → `''`. `FK_RELEASES_FILE` reads the JSON array from disk instead of fetching (sums file resolved next to it by name). `GITHUB_TOKEN` → `Authorization: Bearer`. Any failure (network, non-2xx, no latest) with `FK_REQUIRE_RELEASE=1` throws `Error('Latest release not readable: <reason>')`; otherwise returns what it has (or empty) and calls `warn('releases.unavailable', reason)`.

- [ ] **Step 1: Write the failing tests:**
  - `with-digests`: `latest.tag === 'v1.1.0'`, `latest.assets.find(a => a.name === 'formatkit.exe').sha256` equals the fixture's digest without prefix.
  - `no-digests` + sums file: hashes come from `SHA256SUMS.txt`.
  - `only-prereleases`: `latest === null`, `releases.length === 2`, warning `releases.unavailable`.
  - `empty` without `FK_REQUIRE_RELEASE`: `{ releases: [], latest: null }`; with it: rejects with `/Latest release not readable/`.
  - A fake `fetch` returning status 403: resolves to empty with a warning (Review Focus).
  - A release with `body: null` → `body === ''`.
  - Token: fake `fetch` sees `Authorization: Bearer x` when `GITHUB_TOKEN=x`.
